## Notes

**`0x750` is NOT a single ECU.** It is a **gateway / multi-target relay** that fans out to 22+ downstream ECUs that aren't directly addressable on the OBD-II bus. The gateway selects which downstream ECU to talk to using **ISO 15765-2 mixed addressing**: the first byte of every CAN frame is an address-extension byte (sub-target ID).

### Frame format (mixed addressing)

```
750#XX YY ZZ ZZ ZZ ZZ ZZ ZZ
       │  │  └────┬─────┘
       │  │       └── ISO-TP payload (6 bytes for SF/FF, 7 bytes for CF after seq)
       │  └────────── ISO-TP PCI byte (frame type nibble + length nibble for SF/CF, or first length byte for FF)
       └───────────── address extension (sub-target ECU ID — varies per downstream ECU)
```

Responses on `0x758` echo the same address-extension byte — the tester uses it to correlate which sub-ECU a response came from.

**When parsing 0x750/0x758 frames, always strip the first byte before applying standard ISO-TP rules.** A frame like `750#2A 03 22 10 05` decodes as: sub-target = `0x2A`, ISO-TP single frame (PCI `03` = SF length 3), payload = `22 10 05` (UDS ReadDataByIdentifier 0x1005).

### Behavioural pattern of the `0xE9` probe

When Techstream opens **any** gateway-routed ECU, it first sends a brief 1–2-second exchange with `0xE9`:

```
750#E9 02 3E 00     (Tester Present)
758#E9 02 7E 00
750#E9 02 10 01     (Default Session)
758#E9 06 50 01 00 32 01 F4    (positive resp, P2/P2* timing 50ms/500ms)
750#E9 02 10 03     (Extended Session)
758#E9 06 50 03 00 32 01 F4
750#E9 03 22 20 01  (Read DID 0x2001)
758#E9 05 62 20 01 70 70   (response: 0x7070)
750#E9 02 10 01     (back to Default)
758#E9 06 50 01 00 32 01 F4
```

It's identical every time. This is **not** a probe of an unidentified ECU — it's a healthcheck of Power Source Control before issuing any further requests. After this, Techstream opens the actual target ECU's session normally.

The probe is **cached**: rapid sequential clicks (within ~10 seconds of the previous probe) skip it. Clicks separated by a longer gap re-issue it.

### Implication for the larger ECU inventory

Techstream reports the Solterra has 39 ECUs. Current coverage:
- 18 top-level OBD-II IDs: 13 named functional ECUs + this gateway + 1 virtual Mode 01 server (`0x7E2`) + 3 unknown stubs in the standardized OBD-II range (`0x727`, `0x7E3`, `0x7E6`)
- 22 sub-targets behind this gateway

That gives **36 named ECU identities**. The remaining 3 unknown stubs likely correspond to additional virtual Mode 01/06/09 servers rather than distinct physical ECUs. Other possibilities for any genuinely missing ECU: additional sub-targets on this or another gateway not opened in early ECU-mapping work, or ECUs only addressable when ignition is on.

**Other CAN IDs in this inventory might also be gateways.** Worth a sweep: any ID whose first byte varies across sessions is suspicious. So far only `0x750` is confirmed multi-target.
